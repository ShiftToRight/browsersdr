# Text modem implementation references

Inspected 2026-10-15. These revisions establish reference identity; original recording/publication dates are unknown unless explicitly stated. Generated I/Q checks are not off-air acceptance.

- fldigi source `61b97f4133c488063f3de1795c894d22d5032e8a`, https://github.com/w1hkj/fldigi: `src/cw_rtty/rtty.cxx`, `src/psk/pskvaricode.cxx`, `src/navtex/navtex.cxx`. Inspected character assignments, bit order, rates and framing. Runtime code is original BrowserSDR code; only factual protocol code assignments are transcribed, not fldigi algorithms. ITA2 figures use the international assignment (apostrophe/WRU/bell/plus/pound/equal); the fixed digit vector is independent of the national punctuation variants. BPSK31 implements ASCII 0–127 Varicode, single carrier, 31.25 baud; other PSK families are separate.
- fldigi Users Manual 4.2.00: https://www.w1hkj.org/FldigiHelp/rtty_page.html , https://www.w1hkj.org/FldigiHelp/psk_page.html , https://www.w1hkj.org/FldigiHelp/navtex_and_sitorb_page.html . Clarifies configurable RTTY, phase/timing acquisition, and NAVTEX message framing. Inspected manuals are reference descriptions, not implementation or hardware validation.
- acarsdec source `36f1ccc6c3029d536364dce94aa7665029ad359a`, https://github.com/f00b4r0/acarsdec: `acars.c`, `acarsdec.h`, `msk.c`, `lib.h` and `test.wav`. Inspected ACARS NRZI/MSK, sync, header layout, parity, reflected CRC and ETX/ETB/BCS framing. BrowserSDR uses an original sinusoid-prediction residual detector with five timing hypotheses; upstream decoder code is not incorporated. Independent four-channel audio and reference comparison are documented in `fixtures/README.md`.

Effective I/Q at 1.024, 2.4 or experimental RTL 3.2 MS/s passes through the shared channel reducer, including the existing 4.8/9.6/19.2 MS/s host channelization to 2.4. The 3.2 profile uses exact integer decimation by 50 to 64 ksample/s; 1.024/2.4 retain their 64/60 ksample/s outputs. A second low-pass/tone stage owns narrow text acquisition. Live USB sources retain their actual sample-format metadata; decoder provenance identifies the effective delivered clock and selected offset. There is no inferred receive UTC. Raw I/Q replay flushes workers before EOF; processed remote audio and RTL HF direct sampling require separate integration. Software rate compatibility does not establish loss-free hardware reception.

RTTY and BPSK31 text has no protocol checksum and remains tentative. NAVTEX checks CCIR476 4-of-7 character validity and early/late copies separated by five characters; differing valid copies become erasures, not guessed characters. ZCZC + four-character header and NNNN establish message framing, not correctness or transmitter identity. ACARS requires odd parity and zero CRC residue, retains ACK-only and continuation blocks, and does not merge with ADS-B or decode VDL2. No automatic correction of ACARS frames is attempted.

Independent off-air HF/LF text, reference-decoded NAVTEX recordings, physical live receiver reception, long fading/drift/clock stress, adjacent-channel rejection and extended/browser/device matrices remain acceptance work. The maintained private work log records exactly which checks were run.

## D5/D6 image and Morse additions — inspected 2026-10-15

Original streaming receiver implementations use the same bounded I/Q reducer. Only image-row events cross the worker boundary; one raster (at most 4 MiB) is retained on the main thread, separate from JSON metadata.

- [fldigi WEFAX manual 4.2.00](https://www.w1hkj.org/FldigiHelp/wefax_page.html) and previously pinned fldigi `61b97f4133c488063f3de1795c894d22d5032e8a` `src/wefax/wefax.cxx`: factual IOC, line-rate, shift, 1,900-Hz audio center, APT 300/675-Hz start /450-Hz stop, five-percent white phasing and full-white end-of-phasing. Independent BrowserSDR algorithm, no copied fldigi implementation. Automatic mode requires repeated APT/phasing; manual mode can join a stream. WEFAX has no image checksum.
- [PySSTV](https://github.com/dnet/pysstv/tree/d998fad154d3e6ad2d73af5add49beec0d2ab59f): inspected `pysstv/sstv.py`, `color.py`, `grayscale.py`; factual VIS codes/parity, Martin M1/M2 timings and RGB scan order. Original BrowserSDR decoder. Pinned independent encoder generated the test-only color bars; MIT notice retained. M1 is320×256, M2 is160×256. Other VIS modes are deliberately unsupported. A256-row frame is synchronization-complete, not checksum-verified.
- [ITU-R M.1677-1](https://www.itu.int/rec/R-REC-M.1677-1-200910-I/en), approved2009-10-03: official recommendation listing inspected. PDF retrieval timed out; no full-document inspection claimed. International Morse assignments and1:3 mark /1:3:7 gap wire vectors are tested; no statistical language completion. WPM/threshold and optional timing tracking are explicit. Noisy, fading and hand-sent reception remain tentative.

The SSTV handbook HTML endpoints were inaccessible and its PDF exceeded the web fetch size limit; they are not claimed as inspected protocol evidence. Generated WEFAX/CW and an independently generated SSTV prefix are distinct from off-air/physical acceptance. Source creation dates beyond those explicitly stated are unknown.
